# rapira-windows sync to core 0.8.0

## Context

`../rapira-windows` was forked from core on 2026-07-22 at core commit `26634c8`, right after the NTS merge. Core has since landed 149 commits (+25K/-8K lines): the hyper/tower front replacing pingora, the `\Rapira` namespaced PHP API with classes and the exchange model, dispatcher mode, static files with a cache, tracing logging, host-side multipart, per-connection handlers, release-please. rapira-windows still exposes two global PHP functions, worker mode only, on a pingora front, at ~4K lines. The goal is one clean cut that brings the Windows product to parity with core's surface while keeping its own process model, and leaves the repo shaped so the next sync is a diff.

Decisions taken in this session, all final:

- Process model: ZTS PHP, one process, N interpreter threads. The NTS worker-process alternative was evaluated and verified as feasible but declined.
- Scope: full parity. Three run modes, the complete `\Rapira` API, core's config schema and CLI, hyper front, static files, tracing, uploads, tests, release pipeline.
- Code sharing: vendored mirror. Same crate names and layout as core, platform-neutral files byte-identical, the synced core SHA recorded in the repo.
- Pool: static thread pool plus in-place recycle. Dropped keys: `scaling`, `min_spare`, `max_spare`, `process_idle_timeout_secs`, `request_terminate_timeout_secs`. No reload, no status dump.
- Pool size key: `pool.processes` and `--processes`, same as core. Help text and README state that on Windows it is the interpreter thread count.
- Verification: a Windows 11 ARM64 VM building and running the x64 target under emulation for the fast loop, GitHub Actions x64 runners as the authoritative run.

Windows facts the design rests on, verified against php-src, mio/tokio/socket2/tempfile/tower-http/cc sources and Microsoft docs during planning, then re-checked by an adversarial review of this plan:

- The Zend timer on Windows is a per-thread timer-queue timer that only sets `EG(timed_out)` and `EG(vm_interrupt)`. It fires at the next opcode boundary, so a blocked C call is never interrupted. `zend_set_timeout(0)` does not disarm. Both `zend_set_timeout` and `zend_unset_timeout` can bailout on Windows. `ts_free_thread` does not cancel an armed timer, so a live timer after thread teardown is a use-after-free.
- `ZEND_MAX_EXECUTION_TIMERS` never exists on Windows, so the current guard disables `max_execution_time` per job today.
- Classes, interfaces and enums registered in MINIT before the worker threads exist are visible to every thread. `rapira_mode` may stay a plain global written once before spawn. `ZEND_TLS` and Rust `thread_local!` state is per OS thread, not per interpreter, so an in-place recycle on the same OS thread must reset it. `ts_free_thread` returns the interpreter heap to the OS and the fresh `ts_resource` re-runs the call-stack init, so `rapira_init_call_stack` is not needed.
- `PHP_JSON_API` resolves to `PHPAPI` for consumers, so `php_json_encode` links with no workaround. Every symbol the four new C files reference carries `ZEND_API` or `PHPAPI`. The C shim must not define `PHP_EXPORTS`, `LIBZEND_EXPORTS`, `TSRM_EXPORTS` or `SAPI_EXPORTS`.
- PHP on Windows opens files with `FILE_SHARE_DELETE` and so does Rust std, so unlinking a spooled upload PHP still holds open works.
- `std::net::TcpListener::bind` and mio never set `SO_REUSEADDR` on Windows; the default bind refuses a same-address duplicate and allows an immediate rebind after a stop, with prior connections still winding down. Under the default, a process running as the same user can still bind a specific address under a wildcard listener, or a wildcard under a specific one; a different account gets WSAEACCES. `SO_EXCLUSIVEADDRUSE` would close the same-user case, but Microsoft documents that it can also block a restart while connections accepted by the previous instance are still active. The plan uses the default and documents the residual same-user case.
- `std::process::exit` is `ExitProcess`, which Microsoft documents as able to deadlock when other threads hold locks a DLL detach routine needs. Every forced exit with interpreter threads possibly live must go through `TerminateProcess(GetCurrentProcess(), code)`, which does not return for the calling process and skips every `Drop`. stderr is unbuffered, so log lines written before the call are not lost.
- `seek_read` moves the file cursor. `canonicalize` yields `\\?\` verbatim paths, so containment compares two canonicalized paths. tower-http ServeDir already refuses DOS device names and drive prefixes but treats `\` as a separator on Windows, does not strip trailing dots or spaces, does not reject `:` streams, and resolves NTFS 8.3 short names.
- `GenerateConsoleCtrlEvent` can target one process group only with `CTRL_BREAK_EVENT`, and only when the caller shares a console with the target.
- windows.php.net ships x64 and x86 only, `vs17`, 8.4 and 8.5, with sha256 in `releases.json`. The binary zip needs the Visual C++ Redistributable 2015-2022 x64 on the target machine; neither the zip nor the build provides `vcruntime140.dll`. Of the 17 names in `ci/windows-extensions.txt`, only openssl, curl, mbstring, pdo_sqlite, sqlite3 and fileinfo are DLLs; the rest are static in `php8ts.dll`.
- x64 CI uses `windows-latest` and its native Visual Studio and LLVM tools. The linker consumes the `vs17` PHP import library.
- On an ARM64 host, cc-rs selects `HostARM64\x64\cl.exe` for the x64 target, so no emulated x64 toolset is needed.

### Slice 3: php_sys Rust layer

- Copy core's `src/` wholesale, then apply the deltas below. Byte-identical: `callbacks.rs`, `context.rs`, `classic_worker.rs`, `diagnostics.rs`, `dispatcher.rs`, `executor.rs`, `fold.rs`, `module.rs` (including the `fastcgi` SAPI name on php84 and `ini_defaults`), `rapira_worker.rs`, `types.rs`, `values.rs`, `zend.rs`, `exchange/{headers,request}.rs`.
- `start.rs` (Windows file). Public surface: `Rapira::start(mode)` (one thread, default hooks, used by 158 test call sites) and `Rapira::start_pool(mode, processes, hooks)`, `Rapira::scoreboard()`, `Rapira::shutdown(self) -> bool` (true when every thread joined), `PhpModule`, `check_linked_php`. `start_pool` runs on the boot thread: `php_tsrm_startup_ex(processes + 1)`, `rapira_process_init`, `sapi_startup`, `php_module_startup`, sets `rapira_mode`, creates the `crossbeam_channel::bounded::<Job>(1024)` intake with the shared `pending` counter and a stop channel, creates the scoreboard with one slot per thread, then spawns `processes` named threads (`rapira-worker-N`). `pull_job*` keep their signatures and read a per-thread clone of the receiver from the thread-local; `Pulled::Closed` also fires when the thread-local drain flag is set.
- Thread loop, per thread: `slot.bind(index)` once and install the receiver clone in `JOB_RX` once; neither is ever reset. Then per interpreter generation: `PhpThread::new` (ts_resource, `rapira_thread_init`), reset every per-generation thread-local (drain flag, `quota` state, `DISPATCHER` zval cache forgotten without a dtor, `sb_set(slot)` which also clears `DRAINING`), `quota::install(effective_quota(max_requests, thread_index))`, `info!(target: "rapira", "worker thread {i} ready")`, run `rapira_worker` or `classic_worker` inside `catch_unwind`, on a panic call `exchange::reclaim_current()` so the unit's frame sender and spooled files are released, then `rapira_thread_disarm`, drop `PhpThread`. The drain flag lives for exactly one generation. If the pool is stopping, the OS thread ends. If the generation ended unhealthy (five failed bootstraps or a panic), the loop waits on the stop channel with the backoff schedule copied from core's `process.rs` (100 ms doubling to 25.6 s, streak counter owned by the loop, reset when a generation outlived the quick-crash window), so a stop during a backoff still joins within the grace. Otherwise it rebuilds at once and logs `worker thread {i} recycling`.
- `quota.rs` (Windows delta): `install(max_requests)` per generation; `tick` at quota and `fire_unhealthy` publish `Event::Draining` and set the drain flag and the unhealthy marker directly, no closures. Unhealthy therefore ends the generation under every configuration, including the one-thread `Rapira::start(mode)` the tests use, where core kept shedding 503s on the same interpreter; `failboot_worker_tests` still holds because the next generation sheds the queued job. `PoolHooks { max_requests: u64, on_boot_failure: Arc<dyn Fn() + Send + Sync> }` is the only hook: when a generation ends unhealthy and no slot in the scoreboard has ever handled a request, the loop calls `on_boot_failure` once; the hook only records exit code 70 and trips the stopper, it never exits from a worker thread.
- `handler.rs` (Windows delta): `use crossbeam_channel::{Sender, TrySendError}`, `intake: Sender<Job>`; `FRAME_CAP = 4`, `INTAKE_WAIT`, `PendingGuard` and `HandleError` unchanged. crossbeam disconnects the receivers only when every `Sender` clone is gone, so `HandleError::Stopped` still fires only at real shutdown.
- `scoreboard.rs` (Windows delta): `sb_set` also clears `DRAINING`, so a rebuilt interpreter returns to `SLOT_IDLE`.
- `exchange/receive.rs` (Windows delta): a `forget_dispatcher()` used by the per-generation reset; the SAFETY comments on the two receive shims say the bailout is contained by the C `zend_try`.
- `exchange/respond.rs`: response-channel waits keep the Zend wall timer armed. Helpers that do not access Zend state are safe Rust functions.
- `exchange/sendfile.rs`: decode the PHP path with `String::from_utf8`, reject invalid UTF-8 with `FileNotSendableException`; canonicalize root at boot and target per call, compare verbatim forms. `exchange/mod.rs` `path_bytes` via `to_string_lossy` (only reachable for `Addr::Unix`). `exchange/tests.rs` symlink tests use `symlink_file` and return early on `ERROR_PRIVILEGE_NOT_HELD`.
- Teardown: `Rapira::shutdown(self) -> bool` sets the stopping flag, drops the intake senders, waits the grace, joins, then runs `php_module_shutdown`, `sapi_shutdown`, `tsrm_shutdown` on the boot thread and returns true; if a thread is still live it skips the teardown and returns false. `Drop` runs the same routine and discards the verdict, for the implicit path the tests use. The `_not_send` marker makes `start_pool`, `shutdown` and `Drop` compiler-pinned to the boot thread.
- `Cargo.toml`: `tracing`, `rapira_scoreboard`, `crossbeam-channel`, tokio `["sync","rt","time"]`, `edition.workspace = true`, no `rust-version.workspace`, no empty `[features]` table.

### Slice 5: binary

- `src/main.rs`: copy core, remove `block_early_signals`, the master, the scoreboard creation and `MasterConfig`. Boot order: config, logging, `PidFile::write` (RAII from `src/pidfile.rs`, ported from master, held until `serve` returns), sendfile root (the entrypoint's parent; a missing parent is a boot error), middleware, uploads dir probe and stale-spool sweep, `ExtensionRuntime::new`, `register::<HttpServer>`, `prepare_all` (fails fast on a port conflict before PHP boots), then the worker body inline. Exit codes are computed first: 70 when `on_boot_failure` fired, else 1 when an extension reported an error, else 0. Then `main` returns normally only when `Rapira::shutdown` reported every thread joined; otherwise it calls `TerminateProcess(GetCurrentProcess(), code)`, because returning from `main` is `ExitProcess` and a boot failure by definition leaves the other interpreter threads live. The static-root probe keeps `metadata` and `is_dir`, drops the `join(".")` search-permission probe. The `--listen` help text loses the `unix:<path>` form and the `Listen::Unix` arm in the config-to-http mapping goes.
